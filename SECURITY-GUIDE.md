# Security notes
Implemented: server-side AES-GCM encrypted credentials; salted password hashing; HttpOnly SameSite session cookies, Secure in production; ownership checks on records and tasks; exact-origin checks for state-changing requests; basic process/IP rate limits; bounded JSON inputs; public-only URL resolution with pinned address and network checks; OAuth state + PKCE; manual Gmail confirmation and API result audit; isolated preview CSP and sandbox. Model-generated HTML is untrusted, never execute it on the server. Search results and knowledge passages are untrusted prompt material.

Production checklist: HTTPS, strong unique encryption key, private persistent volume, backups, provider-side budgets, separate test/prod OAuth, ingress firewall, monitor access and logs; do not publish user secrets. Only run one persistent backend instance. Validate real OAuth through deployed proxy, including cookies and CSRF. Security measures are not a certification or an independent penetration test. No MFA, email verification, password recovery, distributed rate limiting, full data encryption at rest, robust secrets redaction guarantee, or comprehensive privacy/account deletion is provided. Do not use for regulated data or public multi-tenant production without a professional review. Local developer DB key is excluded. Rotate compromised credentials at provider; preserve encryption key for existing data. Do not grant write permissions to generic connectors. Gmail send is explicit user action; automations only draft.
